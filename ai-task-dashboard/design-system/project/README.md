複数のAI（Claude・Codex・GLM）に仕事を頼んでいる個人が、作業状況を一目でつかむための画面の規則です。目的は「どの仕事が止まっていて、自分が何を押せば進むか」を最初の3秒で分かるようにすることだけ。装飾で見栄えを足さず、色・記号・言葉の3つで状態を伝えます。

## 原則

1. **止まっている仕事を先に見せる。** 画面の最上部に状況タイル（`SummaryTile`）を置き、「止まっている」「動いている」「終わった」の3つの見出しと件数で全体を示す。一覧も、あなたの返答待ち → AI停止 → 作業中 → 完了 の順に並べる。
2. **黒いボタン＝あなたの番。** `primary` の塗りは「あなたが押せば仕事が進む」ボタンだけに使う（回答する・回答を送信・再試行）。1つの行・1つの区画に1個まで。それ以外は `secondary`（枠あり）か `quiet`（下線の文字）。
3. **状態は色だけで伝えない。** 状態は必ず「印（色の円＋記号）」と「言葉」をセットで出す（`StatusBadge`）。色が見分けにくい人にも、白黒印刷でも読める。
4. **色は状態にだけ使う。** 担当AI・ボタン・見出しには状態色を使わない。担当AIは名前だけで区別する（`AgentTag`）。

## 状態（4種類）

| 状態 | 記号 | 言葉 | 色トークン | 意味 | 一覧での順 |
| --- | --- | --- | --- | --- | --- |
| 確認待ち | ? | 確認待ち | `wait` / `wait-text` / `wait-soft` | AIがあなたの返答を待っている。返答すれば再開する | 1番目・待ちが長い順 |
| AI停止 | ! | AI停止 | `stop` / `stop-text` / `stop-soft` | AI側の問題（制限・タイムアウト等）で止まった | 2番目・停止が長い順 |
| 作業中 | ▶ | 作業中 | `run` / `run-text` / `run-soft` | AIが進めている。あなたの操作は不要 | 3番目・更新が新しい順 |
| 完了 | ✓ | 完了 | `done` / `done-text` / `done-soft` | 終わった。成果を確認できる | 4番目・新しい順 |

- 印は、塗り `wait`・`stop`・`run`・`done`、記号 `on-wait` などの `on-*`、枠 `*-text` の1px で描く。言葉は `*-text`、バッジの地は `*-soft`。
- 「確認待ち」（明るい黄）と「AI停止」（暗い赤）は明度でも 3:1 以上離してある。「作業中」（青）と「AI停止」（赤）は色相と明度の両方で離してある。どの組も記号と言葉が違う。
- 言葉は上の4語に固定する。「エラー」「保留」「進行中」などに言い換えない。長い説明が要る所だけ「あなたの確認待ち」「AI側の問題で停止」を使う。
- 「止まっている」＝確認待ち＋AI停止、「動いている」＝作業中、「終わった」＝完了。この3区分の言葉も固定。

## 言葉づかい

- です・ます調。短く、主語を書く：「Claude が 42分 あなたの返答を待っています」。
- 時間は一覧で相対（「42分待ち」「26分停止中」「3分前に更新」「35分前に完了」）、詳細で絶対（「10/3 13:13」）。
- ボタンは動詞で終える：「回答する」「回答を送信」「再試行」「引き継ぐ」「絞り込みを解除」「取り消す」。「OK」「はい」「送信」だけのボタンは作らない。
- エラー文は「何が起きたか（コード）→ あなたの入力や状態はどうなったか → 次に何をするか」の順に書く。例：「送信できませんでした（通信エラー E-SEND-504）。入力した内容は残っています。もう一度「回答を送信」を押してください。」
- 空状態は「なぜ空か」と「どうすれば埋まるか」を書く。例：「条件に合うタスクはありません。絞り込みや検索の条件を変えるか、解除してください。」
- 絵文字と感嘆符は使わない。

## 色

- 地は `bg`（ページ）・`surface`（パネルと行）・`surface-muted`（詳細の中の区画）の3段。文字は `ink`（本文）と `ink-muted`（補足）の2つだけ。どちらも3つの地の上で 4.5:1 以上（ライト・ダークとも）。
- 区切り線は `line`、操作できる部品の枠は `line-strong`（3:1 以上）。
- 主ボタンは `primary`（= `ink`）の塗りに `on-primary` の文字。ダークでは明るい塗りに暗い文字になる。
- 状態色はバッジ・印・状況タイル・群の見出し・質問と停止理由の囲み（`*-soft` の地＋`*-text` の枠）・エラー文にだけ使う。
- 2つのテーマ（ライト／ダーク）は同じトークン名で切り替わる。値を直接書かず、必ず `var(--トークン名)` で参照する。

## 文字

- 書体は `--font-sans` の1つ。エラーコードとファイル名だけ `--font-mono`（`t-code`）。
- 段階は8つ：`t-title` 20px（画面名）／`t-heading` 16px（区画見出し・状況の要約）／`t-task` 15px（タスク名）／`t-body` 14px（読む文章）／`t-label` 14px 太字（ボタン・ラベル・選択肢）／`t-tag` 13px 太字（バッジ・タグ・チップ）／`t-meta` 12px（時刻・ID）／`t-count` 28px（タイルの件数）。
- 太さは 400 と 600/700 の2種類。強調は太さで行い、色で強調しない。
- 件数・時刻・ID には `.ad-num`（等幅数字）を付ける。
- タスク名は一覧で2行まで（超えたら「…」）、詳細を開くと全文。英数字の長い語（ファイル名など）も途中で折り返す（`overflow-wrap: anywhere`）。

## 余白・角・大きさ

- 4px 基準：`space-1` 4px（印と言葉の間）／`space-2` 8px（部品どうし）／`space-3` 12px（行の上下）／`space-4` 16px（パネルの内側・画面端）／`space-5` 24px（区画どうし）／`space-6` 32px（空状態の内側）。
- 角：`radius-sm` 4px（バッジ・タグ）／`radius-md` 6px（ボタン・チップ・入力・タイル）／`radius-lg` 10px（パネル）／`radius-full`（状態の印だけ）。
- 押せるものは高さ `control-h` 40px 以上。幅 600px 以下では `control-h-touch` 44px にし、主ボタンは横幅いっぱいにする。
- 画面の最大幅は `content-max` 1040px。

## 線・影・選択・フォーカス

- 影は使わない。立体感ではなく、線と地の段差で区画を分ける。
- 選択中（絞り込みチップ・状況タイル・回答の選択肢）は `ink` の2px枠で示し、チップには ✓、タイルには「✓ 絞り込み中」の文字を添える。地の色だけで選択を示さない。
- キーボードフォーカスは `focus-ring`：地色の2px の隙間の外に `focus` 色の2px実線。すべての地の上で 3:1 以上。
- 押せない状態は `surface-muted` の地・`ink-muted` の文字。処理中は文字を「送信中…」などに変え、`aria-busy` を付ける。

## 記号

- 記号は状態の4つ（? ! ▶ ✓）と、選択の ✓、お知らせの i だけ。ほかの装飾アイコンは置かない。
- 記号は bundle の `GLYPHS`（16×16 の SVG、`currentColor`）で描く。文字の ▶ や ✓ は環境によって絵文字になるため使わない。
- ロゴはない。名前は文字で「AIタスク」と書く。

## 画面の組み立て（Dashboard）

上から順に：画面名と最終更新・「更新」ボタン → 状況（止まっている／動いている／終わった の件数タイルと「次にやること」） → 絞り込み（担当AIのチップと検索） → 表示件数 → 状態ごとの群。

- 「次にやること」には、いちばん長く待たせている確認待ちを1件だけ出し、主ボタン「回答する」を置く。確認待ちがなければAI停止を、どちらもなければ「対応するタスクはありません」と書く。
- 行の詳細はその行の真下に開く（別画面やモーダルにしない）。確認待ちは詳細の中で回答し、AI停止は詳細の中で再試行・引き継ぎをする。
- 回答・再試行・引き継ぎの直後、その行は元の群に残したまま「作業中」に変え、結果と「取り消す」を見せる。行を閉じたら新しい状態の群へ移す（目の前から急に消さない）。
- 必ず用意する状態：データ0件／絞り込みで0件／一覧の読み込みエラー（古いデータを残して時点を明示）／送信エラー（入力を残す）／未入力のまま送信。

## 部品の使い方

`components/bundle.js` が `window.AIDash` を作る。ライブラリは不要。各部品は props を受け取って `HTMLElement` を返すので、そのまま `append` する。

```js
document.body.append(
  AIDash.StatusBadge({ status: 'wait' }),
  AIDash.Button({ label: '回答する', variant: 'primary', onClick: open })
);
```

スタイルは `tokens.css` → `components/bundle.css` の順に読み込む。画面全体の組み立て例は「Dashboard」カード。
